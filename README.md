# Threads 農產品貼文流程

這個版本採「自動產生草稿、人工修改或確認、收到明確發布指令才發布」的流程，不會自行把草稿發到 Threads。

完整排程規格集中在 `AUTOMATION_PROMPT.md`，兩台 Mac 使用同一份內容，避免 prompt 各自漂移。另一台 Mac 的設定步驟見 `SETUP_OTHER_MAC.md`。

## 每日流程

1. `daily-agri-check` 在週一至週五完成當日日報。
2. Threads 草稿排程在台北時間 12:30 讀取同一天的日報，13:30、14:30 檢查交付；同日已交付就保持安靜，缺稿才補跑。
3. 從完整日報建立獨立主題清單，同時接受「市場主線與核心判斷」下的 `###` 主題，以及正文中以品種為中心、具備日期、來源、核心數字與完整因果的 `##` 分析段落。標題層級改版不會再卡住流程；沒有新數字的附帶比較、方向速覽或純 radar／watch 資料仍不會被升格。
4. 排除 WTI，將合格獨立主題所屬的糖、玉米、小麥、黃豆、棉花、咖啡、可可與棕櫚油依可比較報價日的絕對漲跌幅排序，再由前往後尋找當日新增事件。價格表可使用「今日價格」或「價格確認」標題；若第一名只有舊事件，就跳到下一個品項，不得拿歷史追蹤內容重貼。
5. 選題前會比對上一個工作日日報與 `drafts/` 內全部舊草稿；相同來源、日期與核心數字視為同一事件。舊事件只有在出現新的原始來源更新、核心數字改變或結果落地時，才可以重新寫成最新進展。
6. 每個工作日都是獨立批次。未發布、等待核准或後來刪除的舊稿只保留紀錄，不會阻擋或取代今天的新草稿；當日日報只要有至少一則未使用的新事件，就必須出新稿。
7. 選定事件後，核對日期、前後數字、整體市場占比、影響與緩衝因素；追蹤檔只補理解這件事所需的背景。
8. 系統在 Codex 對話中交付一篇 500 字元內的「單一事件研究更新」。沒有最低或目標字數，價格與個人判斷都不是內文必填項。
9. 若事件原始報告或新聞內嵌有能直接支援主文的統計圖、趨勢圖、比較圖或資料表，草稿會一併提供截圖；新聞標題、文章文字與商品示意照片不算合適附圖，找不到數據圖表就不附圖。
10. 草稿以手機閱讀為準：每一至兩個完整句子換段，段落之間用零寬空格保留大空行；不把文章切成破碎詞組。
11. 使用者可以貼回修改稿並來回潤飾多次；每次只更新目前候選稿，上一版立即失去發布資格，不會在修改階段自動發布。
12. 使用者清楚回覆「發出」「發送」「可以了」「可以發了」「就這版」「幫我發」或其他明確同義指令時，直接發布目前對話中的最後版本，不再要求第二次確認。
13. 疑問句、流程討論或引用文字不算授權；例如「這樣可以發送嗎？」只是在詢問，不會觸發發布。

草稿文風由 `STYLE_GUIDE.md` 管理。目前試行版本聚焦單一事件：精確日期、前後變化、規模換算、市場影響及緩衝因素；並參考 IEObserve 結論先行、少量關鍵數字與完整因果的節奏，不複製對方原句或固定口頭禪。

## 草稿交付檢查

```bash
python3 draft_workflow.py --thread-id <本機對話-ID> --record
```

檢查器要求「當日當版完整文字」出現在已完成的最終回覆中，才判定已交付。只有草稿檔、只有完成通知、仍在進行中的回覆都不算。已存檔但沒交付時沿用該檔；昨日未核准草稿不影響今天。檢查器完全不讀權杖，也不呼叫 Threads API。

每日日誌存於 `.local/draft-runs/`，保持本機且不進 Git。主流程與補跑使用同一個 heartbeat，並保留本機的對話 ID。原始新聞或圖片重試有時間上限，文字目標在啟動後 15 分鐘內交付。

## 權杖安全

- 長效權杖只存於 macOS Keychain。
- 服務名稱：`com.yuukilin.threads-auto-poster.access-token`
- 帳號名稱：`lin.yusei`
- 權杖不放在 `.env`、GitHub、草稿檔案或程式輸出中。
- 首次設定會跳出 macOS 圖形化安全輸入框，不需要在終端機顯示或輸入權杖。程式以 macOS 原生 Keychain 介面儲存，可完整處理長權杖，不經過指令參數。設定完成時只把固定的本機 helper 列為這一筆權杖的受信任程式，讓背景續期不必每次要求登入密碼；讀取失敗時直接停止，不會退回呼叫通用的 `/usr/bin/security`。

## 唯讀驗證

```bash
python3 threads_api.py verify
```

只會顯示驗證結果、Threads 帳號名稱與帳號 ID，不會顯示權杖。

## 自動續期

長效權杖的期限約為 60 天。macOS 會在每月 1 日 09:15 執行：

```bash
python3 threads_api.py refresh
```

續期後會先確認新權杖仍屬於 `lin.yusei`，通過後才透過 macOS 原生 Keychain 介面更新，並立即讀回比對。權杖不會出現在指令參數、log 或輸出中。最近一次結果保存在 `~/.codex/automations/threads-token-refresh/last-run.json`。

## 發布已核准草稿

對話中的自然語言發布指令會由 Codex 映射成程式唯一接受的固定安全字串 `發送`。這樣可以讓使用者自然下指令，同時保留程式層的精確核准閘門。

```bash
python3 threads_api.py publish --file drafts/approved.txt --approval 發送
```

發布前程式會再次確認權杖屬於 `lin.yusei`。缺少精確的 `--approval 發送` 時，程式會在讀取權杖之前停止。

## GitHub 與跨 Mac

- 沿用既有 `yuukilin/threads-auto-poster` repo，不需要建立第二個 repo。
- GitHub 只保存程式、測試、文風與排程規格；草稿、權杖、log、資料庫與本機執行狀態不會上傳。
- 舊版每三小時自動產文並直接發布的 GitHub Actions 已退役；現在的 workflow 只會執行編譯與單元測試，沒有 Threads 發布權限，也不讀任何發布 secret。
- 共用 Codex 排程定義由私人 `personal-codex-env` repo 同步；每台 Mac 的啟用狀態、模型、推理強度、目標對話與工作目錄維持本機設定。
